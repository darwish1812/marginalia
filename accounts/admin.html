Providers

UseProviderModelKey

The filled dot is the one enrichment uses. Every row carries its own key, so choosing another provider cannot hand a key to an endpoint it was never issued for. Deleting a row deletes its key with it — including the row in use, which switches enrichment off rather than leaving it pointed at nothing.

New provider

The key is written once and never read back. This page can only ever show that one is present and its last four characters — the function will not send more, so a stolen session cannot lift it. An endpoint on this machine needs no key at all, because there is nobody to present one to.

Local model, this machine only

An Edge Function cannot reach a model on your desk, so this page can call it directly — but only from localhost, and only for trying templates. It is not a path any reader can use.

Request

These describe this booklet's task rather than the account, so they stay the same whichever provider is in use. A reasoning model spends most of an allowance thinking: if replies arrive cut off, this is the pair to change.

Template

Assembled server-side. {{WORDS}} and {{FIELDS}} are substituted; the reader's booklet builds the identical string for its Copy prompt button, so the manual fallback stays a true diagnostic. Do not let the two diverge.

Saving runs one real word through the whole path first and shows what came back. A template that stops asking for a field does not fail — it quietly produces plausible output without it, and nothing downstream notices.

Limits

Both ceilings are checked in the same request. A per-reader limit multiplied by an unbounded number of readers is not a budget.

Enrichment

Readers are not offered automatic merging until a test has passed. Send one word and read the Arabic before enabling anything.
